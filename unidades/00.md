## Alcance y uso

Esta guia sintetiza la teoria, las ideas clave, los patrones de codigo y las resoluciones de ejercicios de los cuadernos disponibles entre U00 y U45, junto con los cuatro proyectos integradores P24, P30, P38 y P46. ## U00-U17: fundamentos de Python

### U00. Bienvenida, entorno y metodo de trabajo

- Jupyter combina celdas de codigo y Markdown. `Shift+Enter` ejecuta la celda y avanza; el kernel conserva variables entre celdas.
- El orden de ejecucion puede ser distinto al orden visual. Si los resultados parecen incoherentes, reinicia el kernel y ejecuta todas las celdas en orden.
- Un entorno virtual (`.venv`) aisla dependencias del proyecto.
- `Path.cwd()` consulta el directorio de trabajo; `exists()` comprueba si una ruta existe. Comprobar existencia no garantiza que la ruta sea un archivo.
- Una funcion de informe puede devolver un diccionario estructurado en vez de imprimir el resultado.

### U01. Lenguajes y desarrollo para IA

- Una solucion completa tiene entrada, procesamiento, salida y, cuando corresponde, almacenamiento.
- El desarrollo incluye comprender el problema, disenar, implementar, probar, desplegar y mantener.
- La IA forma parte del procesamiento, no necesariamente de toda la aplicacion.
- La eleccion de lenguaje depende de legibilidad, ecosistema, rendimiento, integracion y mantenimiento.
- El uso de datos requiere pertinencia, autorizacion, cuidado con sesgos y revision humana.
- HTML/XML usan etiquetas, atributos y contenido; las etiquetas deben anidarse correctamente.
- Un aviso de riesgo y la deteccion de un objeto inexistente son problemas distintos: no confundir estados parecidos.

### U02. Como se ejecuta Python

- Python se ejecuta mediante un interprete. Un notebook `.ipynb` organiza celdas; un script `.py` es un archivo de codigo ejecutable.
- Errores de sintaxis impiden interpretar el codigo; errores de ejecucion aparecen al ejecutarlo; errores logicos producen resultados incorrectos sin necesariamente lanzar excepcion.
- El kernel conserva el estado. Reiniciarlo y ejecutar todo comprueba la reproducibilidad.
- La sangria define bloques; se recomiendan cuatro espacios. `#` inicia un comentario.
- Una division por cero produce un error de ejecucion, no un error de sintaxis.

### U03. Valores, tipos y variables

- Tipos basicos: `int`, `float`, `str`, `bool` y `None`. Una variable es un nombre asociado a un objeto/valor.
- `type()` consulta el tipo, `repr()` ayuda a inspeccionar la representacion y `id()` identifica un objeto durante su vida.
- `/` realiza division real; `//` division entera; `%` resto; `**` potencia. Los parentesis controlan prioridad.
- Las conversiones explicitas incluyen `int()`, `float()`, `str()` y `bool()`, pero pueden fallar si el contenido no es valido.
- `"18"` es texto, no un numero; `None` no significa cero.
- Los numeros de punto flotante pueden presentar pequenas diferencias por su representacion binaria. No usar igualdad exacta para toda comparacion numerica.
- Evitar usar nombres de funciones incorporadas, como `list` o `type`, para variables.

### U04. Decisiones y depuracion inicial

- `if`/`elif`/`else` ejecutan el primer bloque cuya condicion resulta verdadera.
- Comparadores: `==`, `!=`, `<`, `<=`, `>` y `>=`. `=` asigna; `==` compara.
- `and`, `or` y `not` combinan o invierten condiciones. Para comprobar ausencia, usar `is None`.
- Las comparaciones encadenadas, por ejemplo `18 <= temperatura <= 27`, expresan intervalos.
- Depurar implica reproducir el fallo, describirlo, reducir el caso, observar valores, formular una hipotesis y cambiar lo minimo.
- Revisar los limites del enunciado: “al menos 15” normalmente incluye 15 y se expresa con `>= 15`.

### U05. Listas, tuplas y rangos

- Las secuencias se indexan desde cero; los indices negativos cuentan desde el final. `len()` devuelve la longitud.
- Un corte `secuencia[inicio:fin:paso]` incluye `inicio` y excluye `fin`.
- Las listas son mutables; las tuplas son inmutables. Una tupla de un elemento requiere coma: `("unico",)`.
- `range(fin)` genera enteros hasta, pero sin incluir, `fin`.
- `append`, `insert`, `remove` y `pop` modifican listas; `pop` tambien devuelve el elemento retirado.
- `b = a` crea otro nombre para el mismo objeto; `a.copy()` crea una copia superficial.
- No asignar el resultado de `append()` a la lista: el metodo modifica la lista y devuelve `None`.

### U06. Bucles y patrones de procesamiento

- `for` recorre elementos; `range` sirve para secuencias de indices; `enumerate(iterable, start=...)` entrega indice y elemento.
- `while` depende de una condicion; debe existir una actualizacion que pueda hacerla falsa.
- Patrones frecuentes: acumulador, contador, filtrado y construccion de una nueva lista.
- `break` termina el bucle; `continue` pasa a la iteracion siguiente.
- Comprobar colecciones vacias antes de dividir por su longitud o calcular minimos/maximos.
- Una media para una lista vacia necesita una politica explicita; devolver cero puede confundirse con una media realmente medida de cero.

### U07. Cadenas de texto

- `str` es una secuencia ordenada e inmutable; sus transformaciones producen nuevas cadenas.
- `strip`, `lower`, `upper`, `replace`, `startswith`, `endswith`, `find`, `split` y `join` son operaciones habituales.
- `find()` devuelve `-1` cuando no encuentra la subcadena.
- `split()` genera partes (a menudo una lista); `join()` se llama sobre el separador para unir textos.
- `repr()` ayuda a descubrir espacios o caracteres invisibles que `print()` puede ocultar.
- Las f-strings insertan expresiones y permiten formatos como `.2f`.
- Comparar una lista obtenida por `split()` con una cadena no es equivalente: revisar el tipo y forma del resultado.

### U08. Diccionarios y conjuntos

- Un diccionario asocia claves con valores. `diccionario[clave]` puede producir `KeyError`; `get(clave, defecto)` permite una alternativa sin insertar la clave.
- `items()` recorre pares clave-valor; `keys()` y `values()` dan vistas de claves y valores. Asignar una clave existente reemplaza su valor.
- Patron de conteo: `conteos[x] = conteos.get(x, 0) + 1`.
- Los conjuntos mantienen elementos unicos; `|` es union, `&` interseccion y `-` diferencia.
- `{}` crea un diccionario vacio; `set()` crea un conjunto vacio.
- Los conjuntos no tienen indices ni cuentan repeticiones. Usar `sorted()` si se necesita una salida con orden reproducible.

### U09. Archivos, rutas y formatos de datos

- `Path` y el operador `/` permiten construir rutas portables. Distinguir rutas relativas y absolutas, y comprobar `exists()` o `is_file()` segun la necesidad.
- `with` cierra archivos aunque ocurra una excepcion.
- `read_text()` y `write_text()` trabajan con texto; especificar UTF-8 evita ambiguedades de codificacion.
- Los modos `w` reemplazan el contenido; `a` anade contenido.
- CSV: `csv.reader` devuelve secuencias de campos; `csv.DictReader` asocia campos con nombres de columna. No separar CSV con `split(",")`, pues las comillas y delimitadores complican el formato.
- JSON representa estructuras basicas: `dump/load` trabajan con archivos; `dumps/loads`, con cadenas. `ensure_ascii=False` conserva caracteres Unicode legibles.
- Verificar existencia con `ruta.exists()` o `ruta.is_file()`, no con `if ruta`.

### U10. Funciones y diseno modular

- `def` define una funcion; parametros aparecen en la definicion y argumentos en la llamada.
- `return` devuelve un valor reutilizable; `print` solo muestra informacion. Una funcion sin `return` devuelve `None`.
- Las funciones pequenas y con una responsabilidad son mas faciles de probar y reutilizar.
- Las pruebas con `assert` deben cubrir caso normal, limites y entradas vacias/invalidas.
- Anotaciones y docstrings documentan; las anotaciones no convierten ni validan tipos automaticamente.
- Evitar valores por defecto mutables compartidos. Decidir y documentar que se devuelve si no hay datos.
- No modificar entradas si el contrato pide no hacerlo; si se modifica una lista, aclarar si la funcion tambien devuelve el resultado.

### U11. Modulos, paquetes y pruebas

- Un modulo suele ser un archivo `.py`; un paquete organiza modulos. Los imports deben ser claros y evitar efectos secundarios.
- `if __name__ == "__main__":` separa la ejecucion directa de la importacion.
- La cache de imports puede hacer que cambios no aparezcan en un kernel activo; reiniciar o recargar segun el caso.
- `pytest` detecta archivos `test_*.py` y funciones `test_*`; se ejecuta desde la raiz del proyecto.
- Un test verifica expectativas concretas, no demuestra que el programa sea perfecto.
- No cambiar una expectativa solo para que una prueba pase: verificar si la regla implementada o la prueba estan equivocadas.

### U12. Ambito, modulos y paquetes

- Variables locales viven dentro de una funcion; variables globales pertenecen al modulo.
- Es preferible pasar datos por parametros y devolver resultados a modificar estado global oculto.
- `global` y `nonlocal` modifican nombres en ambitos exteriores; usarlos solo cuando sea necesario.
- `.venv` aisla dependencias; `requirements.txt` declara dependencias. No copiar el entorno virtual como parte del proyecto.
- Rutas personales y dependencias globales reducen portabilidad. Mantener coherentes estructura e imports.

### U13. Clases y objetos

- Una clase define estado y comportamiento; una instancia es un objeto concreto.
- `__init__` inicializa; `self` refiere a la instancia actual y no se pasa explicitamente al construirla.
- `__repr__` ayuda a depurar; `__str__` busca una representacion legible.
- Composicion modela relaciones “tiene un”: una medicion puede referirse a un aula.
- Los metodos acceden a atributos mediante `self`. Validar invariantes, como ocupacion entre cero y capacidad.
- Condiciones de intervalos se combinan con `and` y comparaciones encadenadas, no con `&` para escalares.

### U14. Herencia y polimorfismo

- La herencia es apropiada cuando una subclase “es un” tipo de su clase base; `super()` permite reutilizar inicializacion o metodos base.
- Polimorfismo permite usar objetos distintos mediante una interfaz comun, por ejemplo llamar `leer()` en una lista de sensores.
- La composicion conviene para relaciones “tiene un”.
- Un metodo redefinido debe mantener un contrato compatible: tipo y estructura de retorno esperados.
- Olvidar inicializar la clase base puede dejar atributos incompletos. Resultados vacios y resultados normales con claves distintas pueden romper al consumidor.

### U15. Excepciones y context managers

- Distinguir errores como `ValueError`, `TypeError`, `KeyError`, `IndexError`, `FileNotFoundError` y `UnicodeDecodeError`.
- `try` cubre instrucciones que pueden fallar; `except` debe capturar errores concretos; `else` corre sin excepcion; `finally` se ejecuta al final.
- `with` gestiona recursos, como archivos, de forma segura.
- `raise ... from error` conserva el contexto de la excepcion original.
- En datos, no reemplazar automaticamente valores invalidos por cero: cero puede ser una medicion valida.
- Elegir deliberadamente entre recuperarse, propagar el error o detenerse; no ocultar errores de programacion con capturas generales.
- Al procesar archivos, conservar fila/campo ayuda a localizar entradas incorrectas.

### U16. Iteradores, generadores y comprensiones

- Un iterable permite iniciar un recorrido; un iterador mantiene el progreso. `next()` obtiene el siguiente elemento y un iterador agotado no vuelve al inicio.
- `for` consume iteradores automaticamente. Una lista puede recorrerse varias veces; un generador normalmente produce valores bajo demanda.
- `yield` pausa y reanuda una funcion generadora. Las expresiones generadoras usan parentesis.
- Comprensiones de listas, conjuntos y diccionarios expresan transformaciones sencillas.
- `zip()` agrupa elementos por posicion y se detiene al agotarse el iterable mas corto.
- Usar bucles explicitos cuando hay validacion, excepciones o efectos secundarios complejos.
- No asumir que una operacion de formato falla por ser un entero: algunos formatos numericos tambien aceptan enteros.

### U17. Decoradores y recursos de Python

- Las funciones son valores: se pueden asignar, pasar como argumento y devolver.
- Un decorador recibe una funcion y devuelve otra que la envuelve; `@decorador` es la sintaxis abreviada.
- El envoltorio debe aceptar argumentos, preservar el resultado y mantener el contrato de errores.
- `functools.wraps` conserva metadatos como `__name__` y docstring.
- Los cierres recuerdan valores del ambito exterior. Anotaciones como `list[str]` documentan, no validan por si mismas.

## U18-U23: Pandas y datos tabulares

### U18. Pandas y datos tabulares

- `Series` es unidimensional; `DataFrame` es una tabla etiquetada. Filas son observaciones y columnas variables.
- `shape` da `(filas, columnas)`; `size` cuenta celdas; `ndim` cuenta dimensiones.
- `read_csv()` carga CSV; revisar rutas, separador, codificacion e inferencia de tipos.
- `head`, `tail`, `sample`, `columns`, `dtypes`, `info`, `describe`, `nunique` y `value_counts` permiten inspeccionar.
- `object` puede indicar texto o mezcla de tipos; `describe()` no garantiza calidad ni representatividad.

### U19. Seleccion, filtrado y calidad de datos

- `df["col"]` devuelve una Series; `df[["col1", "col2"]]` devuelve DataFrame.
- `loc` selecciona por etiquetas; `iloc`, por posiciones. Los extremos de cortes por etiqueta y posicion pueden comportarse distinto.
- Combinar mascaras booleanas con `&`, `|`, `~` y parentesis.
- `isna`, `duplicated`, `drop_duplicates`, `fillna` y `to_numeric(errors="coerce")` ayudan a diagnosticar o limpiar.
- `errors="coerce"` convierte entradas no numericas en `NaN`; no las convierte en cero.
- Trabajar sobre `copy()` preserva la tabla original. Comprobar tipos antes de comparar horas, fechas o numeros.

### U20. Estadistica descriptiva, agrupacion y ordenacion

- Media es sensible a valores extremos; mediana puede representar mejor distribuciones asimetricas.
- `groupby` crea grupos para agregar; `agg` permite multiples estadisticas; `sort_values` ordena resultados.
- `size` cuenta filas de cada grupo; `count` cuenta valores no ausentes.
- Nombrar columnas derivadas con sufijos informativos, por ejemplo `_media`, `_max` o `_lecturas`.
- Una media global no es igual a una media por grupo. Comprender el nivel de agregacion antes de comparar.

### U21. Combinacion de datos, fechas y exportacion

- `merge` combina tablas por claves; una clave primaria suele ser unica y una clave foranea puede repetirse.
- `how="inner"` conserva coincidencias; `"left"` conserva todas las filas izquierdas; `"outer"` incluye claves de ambas.
- `validate` comprueba la cardinalidad esperada; `indicator=True` anade `_merge` para diagnosticar coincidencias.
- `concat` apila/combina estructuras. No sustituye a `merge` cuando se deben emparejar claves.
- `to_datetime(errors="coerce")` convierte fechas invalidas en `NaT`; `.dt` obtiene componentes como ano, mes o nombre del dia.
- Exportar con `to_csv(index=False, encoding="utf-8")` evita guardar el indice si no es dato.
- No borrar claves sin correspondencia antes de investigar que significan.

### U22. Visualizacion exploratoria con Pandas y Matplotlib

- Elegir grafico segun pregunta: lineas para secuencias ordenadas, barras para categorias, histograma para distribucion, dispersion para relaciones y boxplot para distribuciones por grupo.
- Un boxplot resume mediana, cuartiles y posibles valores alejados; no representa solo minimo y maximo.
- Usar titulos, etiquetas, unidades y limites honestos; `savefig` exporta.
- La asociacion visual no demuestra causalidad. Tener en cuenta tamanos de muestra y escala.

### U23. Eficiencia, transformaciones y texto

- Las columnas categoricas pueden ahorrar memoria cuando hay pocos valores distintos respecto del total; comprobar con `memory_usage(deep=True)`.
- Preferir operaciones vectorizadas y metodos `.str` sobre bucles o `apply(axis=1)` cuando sea claro y equivalente.
- `map`, `apply`, `np.where`, `astype` y `pd.cut` transforman o clasifican datos.
- `.str.strip`, `.replace`, `.upper`, `.fullmatch` y `.extract` limpian o analizan texto.
- `fullmatch` exige que toda la cadena coincida; `extract` obtiene grupos y puede producir `NaN` sin coincidencia.
- Mantener columnas originales cuando se necesita trazabilidad de la transformacion.

## U25-U29: NumPy

### U25. Arrays, tipos y creacion

- `ndarray` representa datos homogeneos multidimensionales. `shape`, `ndim`, `size`, `dtype` e `itemsize` describen forma y almacenamiento.
- Crear arrays con `array`, `zeros`, `arange`, `linspace` o `eye`.
- Las operaciones pueden cambiar tipo: division de enteros puede producir flotantes; convertir luego a entero puede perder decimales.
- Interpretar ejes del problema: por ejemplo `(sensores, horas, variables)`.

### U26. Indexacion, mascaras y copias

- Indexacion `array[fila, columna]`, cortes `:` y mascaras booleanas seleccionan elementos.
- La asignacion con mascara permite modificar coincidencias de forma vectorizada.
- Un corte puede ser una vista que comparte memoria; `.copy()` crea una copia independiente.
- Combinar condiciones con `&` y `|` usando parentesis. `array_equal` comprueba igualdad exacta.

### U27. Vectorizacion, broadcasting y agregaciones

- Las operaciones elemento a elemento aplican sobre arrays sin bucles explicitos.
- Broadcasting permite operar entre formas compatibles, por ejemplo un vector de columnas sobre todas las filas.
- `mean`, `min`, `max`, `std` y `sum` aceptan ejes; comprender si el resultado resume filas o columnas.
- `where` selecciona segun una condicion. Normalizacion min-max debe tratar el caso de rango cero.
- Cuidado: `where` no siempre evita que una expresion problematica, como division por cero, se evalue previamente.

### U28. Forma, combinacion y preprocesamiento

- `reshape` reorganiza dimensiones sin cambiar numero de elementos; `-1` infiere una dimension compatible.
- `flatten()` siempre crea copia; `ravel()` puede devolver vista. `T` transpone ejes.
- `vstack`/`hstack` combinan arrays; `vsplit` los divide.
- En datos para modelos, normalmente las observaciones son filas, las variables predictoras columnas y `y` la etiqueta.
- Verificar `shape` despues de cada transformacion; separar, por ejemplo, `X = matriz[:, :-1]` y `y = matriz[:, -1]`.

### U29. Algebra lineal y estabilidad numerica

- `A * B` multiplica elemento a elemento; `A @ B` realiza producto matricial.
- `np.linalg.solve(A, b)` resuelve `Ax=b`; preferirlo a calcular `inv(A) @ b`.
- Determinante cercano a cero puede indicar singularidad; numero de condicion alto indica sensibilidad a errores.
- `norm` calcula magnitud; `allclose` verifica igualdad aproximada con tolerancia.
- No depender de `==` exacto para numeros flotantes.

## U31-U37: visualizacion con Matplotlib

### U31. Proposito, figuras, ejes y lineas

- `Figure` es la superficie general; `Axes` es el area con datos, marcas, etiquetas y leyenda.
- `fig, ax = plt.subplots()` crea figura y ejes; `ax.plot()` dibuja series.
- Ordenar datos antes de trazar: una linea conecta puntos en el orden recibido.
- Comunicar pregunta con titulo, unidades, etiquetas y leyenda. Una categoria sin orden no siempre debe unirse con linea.

### U32. Series y comparaciones temporales

- Convertir fechas, ordenarlas y verificar monotonia antes de graficar.
- Comparar series solo con unidades y periodos compatibles; magnitudes incompatibles suelen necesitar paneles separados.
- Revisar escalas, rango vertical, marcas de fecha, longitudes y diferencias maximas.
- Un eje recortado puede exagerar cambios; explicar el rango utilizado.
- Un grafico ayuda a ver que ocurrio y cuando, pero no explica por si solo por que.

### U33. Relaciones y diagramas de dispersion

- Un punto representa una observacion; dispersion explora asociacion entre variables cuantitativas y posibles grupos o valores atipicos.
- Categorias se pueden mapear a color/forma; una tercera variable numerica puede mapearse a tamano, con leyenda comprensible.
- `alpha` ayuda con solapamiento; colores, tamano y marcadores deben mejorar legibilidad, no decoracion.
- Asociacion visible no demuestra causalidad ni que la relacion sea lineal.

### U34. Distribuciones y datos categoricos

- Histograma agrupa valores numericos en bins; barras comparan categorias.
- El ancho y numero de bins pueden cambiar la forma percibida; usar criterios comparables.
- Barras horizontales ayudan con etiquetas largas; `bar_label` anota valores.
- Frecuencia y densidad tienen significados y escalas diferentes; indicar cual se muestra.

### U35. Figuras compuestas, diseno y exportacion

- `subplots` crea paneles; `sharex/sharey` puede facilitar comparaciones cuando las escalas son compatibles.
- Titulos globales, anotaciones y `tight_layout` mejoran organizacion.
- `savefig` permite formato, `dpi` y `bbox_inches`; crear carpeta y usar ruta reproducible.
- Revisar la imagen exportada, no solo el resultado dentro del notebook.
- Evitar texto cortado, rutas absolutas y paneles sin unidades.

### U36. Matrices e imagenes como datos

- `imshow` presenta matrices como mapas de color; cada celda puede codificar magnitud, conteo o pixel.
- Usar `colorbar` para relacionar color y valor; `vmin/vmax` facilitan comparaciones con escala fija.
- `origin` afecta orientacion; los indices de matriz no son automaticamente coordenadas del mundo.
- Diferenciar escala de grises, matrices normalizadas y canales RGB. Anotar valores solo si mejora lectura.

### U37. Comunicacion visual de resultados de IA

- Curvas requieren ejes, umbrales y escalas comparables; matrices de confusion requieren orden de clases y orientacion real/predicho claros.
- La diagonal muestra aciertos por clase; fuera de diagonal, errores entre clases.
- Exactitud global puede ocultar rendimiento desigual; revisar precision, cobertura/recall y F1 por clase.
- Al normalizar la matriz, declarar si filas o columnas suman uno/cien por ciento.
- Comunicar hallazgo, limitaciones, incertidumbre y siguiente comprobacion; no afirmar mas de lo que respaldan los datos.

## Proyecto P38: informe visual reproducible con Matplotlib

- **Hito 1, contrato de datos:** auditar tres CSV (curvas, conteos largos y metricas); verificar columnas, tipos, nulos, iteraciones 1-8 y clases A/B/C.
- **Hito 2, matriz y metricas:** pivotar filas reales y columnas predichas, reindexar clases y convertir a matriz 3x3; comparar con datos precomputados.
- Precision por clase divide diagonal por suma de columna; cobertura/recall divide diagonal por suma de fila; traza suma aciertos.
- **Hito 3, figura:** tres paneles para curvas, matriz de confusion y metricas; incluir escalas, etiquetas, colorbar y leyendas.
- **Hito 4, exportacion:** guardar PNG con ruta relativa, resolucion definida y comprobar existencia; redactar texto alternativo con resultado, limites y proxima comprobacion.
- Las metricas y conteos son precomputados: la visualizacion no establece causalidad.

## U39-U45: visualizacion estadistica con Seaborn

### U39. Seaborn, datos y gramatica visual

- Seaborn facilita graficos estadisticos sobre DataFrames y usa Matplotlib.
- Mapeos comunes: `x`, `y`, `hue`, `style`, `size`; cada uno asigna variable a posicion o apariencia.
- Funciones de nivel de ejes como `scatterplot` reciben/crean un `Axes`; funciones de nivel de figura como `relplot` administran figura y pueden facetar.
- Validar ruta, tipos y columnas antes de graficar; elegir mapeos segun pregunta.

### U40. Distribuciones y calidad de una variable

- Histograma cuenta observaciones por intervalo; KDE estima densidad suavizada; ECDF muestra fraccion acumulada sin escoger bins.
- KDE depende de suavizado y puede aparentar formas/colas; no son los datos originales.
- Revisar ausencias como desconocidas, no como ceros; analizar calidad antes de interpretar distribucion.
- Comparar grupos con escalas y parametros consistentes.

### U41. Relaciones entre variables

- Dispersion muestra observaciones; lineplot puede agregar valores repetidos de X.
- Comprobar duplicados por combinacion antes de una linea cuando cada punto debe ser una observacion unica.
- Regresion muestra una tendencia modelada; atipicos, curvatura y dependencia pueden afectar su interpretacion.
- Correlacion y ajuste no demuestran causalidad; considerar diseno y variables omitidas.

### U42. Comparaciones categoricas

- `countplot` muestra conteos; `barplot` presenta una estadistica agregada (normalmente media) y puede incluir incertidumbre.
- `boxplot` resume cuartiles/mediana; `violinplot` muestra densidad; `stripplot` y `swarmplot` muestran observaciones.
- Combinar resumen y puntos ayuda a no esconder distribucion ni tamano de muestra.
- Al superponer capas pueden duplicarse leyendas; conservar solo entradas necesarias.

### U43. Matrices y mapas de calor

- `corr()` calcula correlacion entre variables numericas; las correlaciones lineales van de -1 a 1.
- `heatmap` necesita escala interpretable; una paleta divergente centrada en cero es adecuada para correlaciones positivas/negativas.
- La matriz simetrica puede ocultar un triangulo con mascara. La diagonal de correlacion es uno.
- `pivot_table` resume datos por filas/columnas; `crosstab` cuenta combinaciones de categorias.
- Clustermap reordena para explorar similitudes; no prueba que los grupos sean reales o causales.

### U44. Facetado y exploracion multivariable

- `FacetGrid`, `relplot` y `catplot` separan paneles por categorias; filas/columnas definen facetas y `hue` codifica otra dimension.
- Las mismas escalas ayudan a comparar paneles; demasiados paneles o variables saturan la figura.
- `pairplot` muestra relaciones por pares; conviene seleccionar variables relevantes.
- Facetas dividen observaciones entre paneles; `hue` conserva los grupos dentro del panel.

### U45. EDA reproducible y comunicacion

- Flujo trazable: validar origen y calidad → preservar datos crudos → transformar/copiar → resumir → visualizar → interpretar → exportar.
- `groupby`, `pivot_table` y `cut` generan resumenes/intervalos; comprobar unidades y nivel de agregacion.
- Accesibilidad: no depender solo del color; titulos, etiquetas, leyendas y escalas deben ser informativos.
- Rutas relativas y salidas verificables hacen el analisis portable; documentar fuente y parametros.
- Separar descripcion observada, interpretacion y conclusion; evitar causalidad y extrapolacion no respaldadas.

## Comparaciones que conviene memorizar

| Conceptos | Diferencia esencial |
|---|---|
| `=` y `==` | Asignacion frente a comparacion |
| `print` y `return` | Mostrar frente a devolver un valor |
| Lista y tupla | Mutable frente a inmutable |
| Lista y conjunto | Conserva orden/repeticiones frente a elementos unicos sin conteo |
| Iterable e iterador | Se puede recorrer frente a objeto que mantiene el estado del recorrido |
| Vista y copia | Comparte memoria potencialmente frente a datos independientes |
| `loc` e `iloc` | Etiquetas frente a posiciones |
| `size` y `count` | Cuenta filas/elementos frente a valores no ausentes |
| `merge` y `concat` | Combina por claves frente a apila/combina ejes |
| `inner`, `left`, `outer` | Solo coincidencias; conserva lado izquierdo; incorpora ambos lados |
| `*` y `@` en NumPy | Elemento a elemento frente a producto matricial |
| `flatten` y `ravel` | Copia frente a vista cuando es posible |
| Histograma y barras | Intervalos numericos frente a categorias |
| Conteo, media y distribucion | Frecuencia; resumen agregado; forma/variabilidad de observaciones |
| Eje y figura en Seaborn | Grafico sobre `Axes` frente a objeto de figura que puede facetar |
| Histograma, KDE y ECDF | Conteos por bins; densidad suavizada; fraccion acumulada |
| Correlacion y causalidad | Asociacion medida frente a causa, que requiere evidencia/diseño adicional |
| Precision y cobertura/recall | Fiabilidad de positivos predichos frente a positivos reales recuperados |
| `NaN` y cero | Ausencia/desconocido frente a valor medido |

## Lista de comprobacion para resolver ejercicios

1. Identificar la pregunta, entradas, salidas y unidad de cada variable.
2. Inspeccionar forma, columnas, tipos, rangos, ausencias, duplicados y claves.
3. Preservar datos originales antes de limpiar o transformar.
4. Verificar limites, denominadores, categorias y dimensiones antes de operar.
5. Escoger una representacion que responda la pregunta y rotular escalas/unidades.
6. Comprobar que los resumenes representan el grupo y estadistica que se pretende comparar.
7. Probar casos normales, limites, entradas vacias e invalidas; no ocultar excepciones.
8. Distinguir dato observado, calculo, interpretacion y afirmacion causal.
9. Hacer reproducible la ejecucion y comprobar los archivos exportados.
10. Comunicar limitaciones, incertidumbre y que datos o pruebas adicionales hacen falta.
